### 3.2 公式变量（RPG Maker MV 约定）

| 变量 | 含义 | 本工程对应字段 |
|---|---|---|
| `a` | 攻击方 | `room["player"]` / `room["enemy"]` |
| `b` | 被击方 | 同上，另一侧 |
| `.atk` | 攻击 | `attack`（= melee + shoot） |
| `.def` | 防御 | `defense`（= armor） |
| `.mat` / `.mdf` | 魔攻 / 魔防 | 本工程未单列 → 分别沿用 `attack` / `defense` |
| `.agi` | 速度 | `initiative` |
| `.luk` | 幸运 | 无此字段 → 0 |
| `.hp` / `.mhp` | 当前 / 最大 HP | `hp` / `max_hp` |
| `.mp` / `.mmp` | 当前 / 最大 MP | `mp` / `max_mp` |
| `.level` | 等级 | `level` |

`a.def` 在 Python 里是关键字冲突，求值器内部会自动改名（`normalize_formula`），**不影响公式原文**。

### 3.3 完整结算链（复刻 `rpg_objects.js`）

```
1. base  = max(eval(公式), 0)               ← 负值一律夹到 0
           ×(-1) 若 damage_type ∈ {3 HP吸收, 4 MP吸收}
2. value = base × element_rate               ← 属性倍率，本工程暂为 1
3. if 物理: value ×= 目标.pdr                 ← 物理伤害率，暂为 1
4. if 魔法: value ×= 目标.mdr                 ← 魔法伤害率，暂为 1
5. if base < 0: value ×= 目标.rec             ← 被恢复率，暂为 1
6. if 暴击: value ×= 3                        ← applyCritical，固定 ×3
7. value = applyVariance(value, variance)    ← 三角分布，±variance%
8. value = value / (2 × 目标.grd) 若目标防御中  ← applyGuard，防御减半
9. value = round(value)
```

**暴击**：`itemCri = damage.critical ? 攻击方.cri × (1 - 被击方.cev) : 0`，本工程默认 `cri = 5%`。

**`variance: 20`** 意为 ±20%，分布是**三角分布**（不是均匀分布）：
`amp = floor(|damage| × variance / 100)`，`v = randint(0,amp) + randint(0,amp) - amp`。

对应实现：

```python
from services.skill_formula import make_damage_value
r = make_damage_value("a.atk * 5 - b.def * 1 + 2000", attacker, defender,
                      variance=20, critical_enabled=True)
r["value"]      # 最终伤害
r["critical"]   # 是否暴击
```

## 四、Z_ 插件里挖到的机制

### 4.1 `Z_Xinglevel.js` —— 星级 / 成长 / **悟性**

```
_star          初始 1 星
_growth        成长值 40–100（80% 概率随机；20% 走特值组 60/80/100）
_comprehension 悟性值 40–100（同上）
```

**升星**（每次升级判定一次）：
```
Math.random() * 240 < _growth        → 升 1 星
每星加成：rate = Math.random() * (0.12 - 0.08) + 0.08   → 8%~12%
          8 项基础属性 _paramPlus 各 += floor(paramBase × rate)
```

**悟性学技能**（升级时）：
```
randomValue = Math.random() * 10
if (randomValue < _comprehension && !hasSkill(skillToLearn)) learnSkill(skillToLearn)
```
`skillToLearn` 是插件参数（默认 4）。

> ⚠ **这里有 bug**：`_comprehension` 取值 40–100，而 `Math.random()*10` 范围 0–10，
> 条件**恒为真** → 每次升级必学。按语义应该是 `Math.random() * 100 < _comprehension`
> （即「悟性% 概率习得」）。这正是你说的「升级概率习得悟性技能」。
> 本工程实现时按**修正后的语义**走，概率 = `悟性%`。

### 4.2 `Z_SkillLevel.js` —— 技能等级（Lv1–4）

**等级倍率**（覆盖 `makeDamageValue` 结果）：
```
Lv1 ×1.0   Lv2 ×1.2   Lv3 ×1.3   Lv4 ×1.5
value = floor(baseDamage × multiplier)
```

**两条升级途径**：

| 途径 | 条件 |
|---|---|
| 自动（升级时） | `comprehension/100 × 0.1` → 悟性 40–100 时约 **0.4%–1%** 每次升级、每技能 |
| 手动（花技能书） | Lv2 需 1 本 + 角色等级 25；Lv3 需 2 本 + 等级 40；Lv4 需 3 本 + 等级 50 |

**技能 ↔ 技能书映射**（`SKILL_BOOK_MAP`，原工程写死）：

```
3→36  14→37  15→38  16→39  17→40  18→41  19→42  20→43
21→44 22→45  23→46  24→47  25→48  26→49  27→50  28→51  10→56
```

与 `server/data/Skills.json` 的 `book_id` 字段一致。

**技能图标映射**（`getSkillIconFilename`，原工程草稿）：
```
skillId 18 / 23  → skill_4（悟性攻击）
skillId 29       → skill_3（自动触发）   ← 与我们的分类一致 ✔
skillId 13–28    → skill_1
```
> 18（雷霆冲击）/ 23（电磁风暴）在草稿里被判为 "悟性"，与本工程的
> 「悟性 = 纳米攻击 / 弱点攻击」不符，**以本工程的 `category` 字段为准**。

### 4.3 `Z_GamePlay.js` —— 自动恢复（生命恢复的原型）

```js
// 升级时 10% 概率学会技能 29（自动恢复）
Game_Actor.prototype.levelUp → if (Math.random() < 0.1) this.learnSkill(29);

// 每回合结束自动施放
Game_Battler.prototype.onTurnEnd → if (isLearnedSkill(29)) {
    var action = new Game_Action(this); action.setSkill(29); action.apply(this);
}
```

RPG 里「自动恢复」(id 29) 的定义：`scope 7`（自己）、`occasion 3`（菜单不可用）、
效果 `{ code: 11, dataId: 0, value1: 0.15 }` = **恢复 15% 最大 HP**。

这是本工程「生命恢复」的直系原型；我们把 `ratio` 拆成了可配置项（现在是 5%，**待你定**）。

### 4.4 `Z_skill.js` —— 技能书职业限制

```
格斗技能书：36–40（+55）
射击技能书：41–45（+55）
全能技能书：46–51（+55）
```
55 = 技能书-自动恢复，**三个职业都能用** → 对应本工程的「通用」类。
职业 ID 白名单见 `Z_skill.js` 头部注释（格斗 35 个 / 全能 33 个 / 射击 30 个）。

## 六、和现有战斗服务的差异（接入前必看）

`server/services/battle_room_service.py::_exec_action` 现在是：

```python
raw_damage = int(attacker["attack"]) - int(defender["defense"])
damage = max(1, raw_damage)
```

**这是一条临时的线性减法**，没有技能概念、没有公式、没有暴击/浮动/防御。

接技能时要动的点：

1. `ActionType` 目前只有 `ATTACK / DEFEND / ESCAPE`，需要扩一个带 `skill_key` 的指令；
2. `_exec_action` 改为查 `Skills.json` → `make_damage_value(...)`；
3. **战斗房间目前是 1v1**（`room["player"]` / `room["enemy"]` 各一个）。
   `scope=2`（群体）在 1v1 里退化成单体，等多人战斗落地后 `is_all_target()` 才会真正生效；
4. `mp` 已经存在（上一轮为「能量恢复」加的），技能 `mp_cost` 可以直接扣；
5. `Skills` 数组现在同时承担「被动解锁」和「已学技能」，建议拆开：
   `Skills` 保留已学技能列表，被动用 `PassiveSkills`。

**`mpCost` 需要换算**：原工程 MP 上限是几千量级（技能动辄 2000），
本工程 `MaxMP` 单位不同。要么按「占上限百分比」换算，要么直接把 `mp_cost` 当占位值重设。
