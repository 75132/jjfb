## 三、可执行建议

1. **`wrapMode`**：24 条 `.anim` 目前是 `2`（Loop，沿用既有 Monster/Robot 格式）。技能特效是一次性表现，建议改 `1`（Normal），播完由代码收尾——现在代码里有 `FINISHED` + `scheduleOnce` 双保险，Loop 也不会卡，但语义不对。
2. **单帧特效**：`jiguang01`、`lizi` 只有 1 帧 0.1s，几乎瞬间消失。要么在原包 `xg1.mrp`/`xg2.mrp` 里确认是否漏帧，要么按「静态图 + 代码补时长」处理。
3. **`buff` / `debuff`**：建议不并入技能表，单独立「状态图标动画」层（对应 `tecbuff.mrp` / `state1.mrp`）。
4. **技能书与动画是两套命名**：技能书（光刃斩/火焰风暴/虚空导弹…）原客户端资源里找不到同名特效，若这批书是自建内容，需要另配特效或改用上表 24 个动画里的对应项。

## 四、画布缩放口径（★2026-10-01 用户拍板 · 两类特效两套口径）

用户原话①：「**从 RPG 里搬出来的特效不要放大，他本来是贴合的，你放大了导致我的特效不全；
所以 RPG 移植过来的特效就原比例，我自己的素材的不用维持原样就好。**」
用户原话②（看完预览图）：「**你给我这个图怎么是不全的，被裁了？**」

| 来源 | 数量 | 生成器 | 缩放 | 画布 |
|---|---|---|---|---|
| **RPG Maker 特写动画** | 15 | `tools/rpg_anim_port.py` | **1×（原比例）** | **= 全动画图元并集**（192×192 ~ 1246×696） |
| **用户自己的素材**（xg1/xg2 导出 gif） | 24 | `tools/skill_gif_port.py` | **2×（保持不动）** | 按各自原帧 ×2 |

### 4.1 「被裁」的真根因 = 画布写死 192（不是缩放）

MV 的实际渲染方式（`js/rpg_sprites.js` `Sprite_Animation`）**不是**「一张 192×192 位图」：

```js
Sprite_Animation.prototype.createCellSprites = ... // 16 个独立 Sprite，anchor 0.5
Sprite_Animation.prototype.updateCellSprite = function (sprite, cell) {
    sprite.setFrame(sx, sy, 192, 192);
    sprite.x = cell[1];   // ← 图元偏移可以远超 ±96
    sprite.y = cell[2];
    sprite.rotation = cell[4] * Math.PI / 180;
    sprite.scale.x = cell[3] / 100;
};
Sprite_Animation.prototype.updatePosition = ...
    if (this._animation.position === 3) {   // 画面级：锚在**屏幕中心**，不是目标
        this.x = this.parent.width / 2;
```

**所以 MV 从来不裁**。原先的移植固定用 192×192 画布 + `Image.paste`，超出的图元被静默丢弃：

| clip | 图元 x 范围 | 超出 192 格的图元 |
|---|---|---|
| 虚空导弹（id 110，position=3） | [-408, 312] | **211 / 251** |
| 能量爆破（id 109） | [-300, 312] | 18 / 58 |

→ 现改为 `anim_window()`：先算**整段动画所有图元**（含旋转/缩放的精确 AABB）的并集，
画布按并集开（下限锁死原生 `[0,192]`，普通贴目标动画取景**完全不变**），再统一裁到实际 alpha 并集 bbox。

那 4 帧原先的图元**全在 192 格之外**，被当成「全空帧」剔掉了，现在回来了。

⚠ **代价（已知，未规避）**：画面级动画本来就是一屏大小，逐帧合成后 15 个 clip 的
RGBA 合计 ≈ 747 MB（旧 192 方案 ≈ 54 MB）。MV 之所以便宜，是因为它用 16 个
cell Sprite 共享图集位图；本工程是「一帧一张 PNG」的帧序列，成本记在帧上。
若日后要压，方向是「改成 cell 分层播放」而不是裁画布。

- ⚠ **重生成必须保 uuid**：生成器已加 `existing_uuid()` 复用逻辑 —— 帧 `.png.meta` 与 clip `.anim.meta`
  的 uuid 一律沿用旧值。否则 `assets/UIPrefab/RobotShow.prefab` 里 Animation 播放列表按 uuid 引用 clip，
  换 uuid 会让特效**静默播不出来**（2026-10-01 已踩过一次，已修）。
- ⚠ **改尺寸后必须同步编辑器 `library/` 缓存**（`python tools/_sync_skill_library_cache.py --apply`）：
  帧是原地替换（uuid 不变）但尺寸变了，编辑器 `library/**@f9941.json` 还留着旧 `rect`，
  会刷 `[Scene] Rect width exceeds maximum margin: xxx/ 384 192`（169 条）。
- 守卫测试：`tools/_test_skill_anim_assets.py`（**85 项**，已进 `_skill_regression.py`）——
  `UPSCALE==1` / `SCALE==2`、15 个 clip 帧数快照、帧尺寸一致且 ≥192、
  **★防裁实证（`--check`：画布 +64px 重渲染后 bbox 只许平移）**、`_values` 引用与帧 meta 一一对应、
  prefab 引用全命中、**library 缓存一致**。
- 生成器自带自检：`python tools/rpg_anim_port.py --check`。
