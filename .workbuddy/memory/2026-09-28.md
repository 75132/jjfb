## 【续3·定案】战斗卡死真因 = `scheduleOnce(同一函数引用)` 被 Cocos 去重（2026-09-28 晚）
**日志 `temp/logs/project.log` 抓到确切断点**（`[攻击诊断]` 插桩立功）：
```
段 1/2 → 段 2/2 → 段结算收尾 → onDone   ← 敌方(2段) 完美
段 1/4 → 段 2/4 → (无日志) → 看门狗超时12s  ← 玩家(4段) 断在第2段后
段 1/4 与 段 2/4 间隔约 1s（应为 0.18s）
scheduler#scheduleSelector. Selector already scheduled. Updating interval ...
```
- **根因**：Cocos 的 `scheduleOnce(callback, delay)` **以 target+callback 为唯一键做去重**。`step` 递归调用 `this.scheduleOnce(step, 0.18)` 时，上一次调度尚未从队列移除 → 命中「already scheduled」→ **不新建调度、只更新已有 interval** → 第 2 段后再也不执行。
  - 敌方 2 段只需 1 次递归（去重只造成延迟，不丢）；**玩家 4 段需 3 次递归 → 第 2 次即被吞掉 → 永久卡 ANIMATING**。这解释了「敌方先手正常、玩家攻击卡死」的现象差异。
- **修复**：所有「自我递归 `scheduleOnce`」一律包一层**匿名闭包** `this.scheduleOnce(() => step(), 0.18)`，保证每次 callback 引用唯一。改了两处：`performAttackWithDamage`（联机，行~2196）与 `performAttack`（本地，行~1879）。
- **附带优化**：`playAttackAnimation` 的 2.2s 兜底提到 `let animFallback` 变量，`fireComplete` 完成时 `this.unschedule(animFallback)` 主动清理，避免每次攻击往 scheduler 堆积定时器（该堆积正是加剧调度污染的元凶）。
- **验证**：`tsc -p tsconfig.json` → BattleScene/RobotShow 零错误。
- **铁律（重要通用规律）**：**Cocos 中「同一个函数引用」用 `schedule/scheduleOnce` 重复注册（尤其自我递归）会被去重，导致调度丢失**。凡递归/重复调度必须用匿名闭包包装，或用唯一 callback。这是本次卡死的根本原因，也是最难排查的一类问题（无异常、无报错，只表现为"卡住"）。

### 【续15】模拟端登录拿不到 character_id → 已修复（两处真 bug）

**用户报错**：`登录成功 user_id=null character_id=null` → 反复「缺少 character_id，无法匹配」。

**根因 1：`login_response` 不含 `character_id`，且 `user_id` 在【根级】不在 data。**
- 服务端 `login_handler.handle_login` 成功分支用 `send_direct_response`，返回根级
  `{type:'login_response', success, message, token, refresh_token, ..., user_id}`——**没有 character_id**。
- 而 `pvp_flat_match` 强制要求 `character_id`（`pvp_match_handler.py` 第 38-46 行，无则 400「未选择角色」）。
- **登录 → 选角 是两段式**：`login`（拿 user_id+token）→ `get_all_characters` → `select_character`（拿 character_id）。

**根因 2（真正的隐蔽 bug）：请求-响应 route 匹配未归一化。**
- 页面 `send(type, body, waitFor)` 的 route 兜底匹配用的是 `pendingReq[k].route === t`，

  而服务端响应 `type` **恒为 `<route>_response`** → 兜底永不命中 → 一旦服务端响应不带 request_id
  （`send_error_response` 场景）就傻等 15s 超时。

**实测确认的服务端真实结构**（`tools/pvp_sim/probe_login2.py`、`probe_chain.py`）：
- `login_response` 根级 `user_id="69cdeedc17d8322502e247e2"` + token；`data=None`。
- `all_characters_response` 全部键 `['characters','request_id','success','type','version']` →
  **根级 `characters`**（dict）`{"0":{slot_index:0, character_id:"8c194029-...", role_name:"李贵",...}, "1":{...}, "2":null}`；`data=None`。
- `select_character_response` `{success:true, character_id:"8c194029-..."}`。
- `pvp_flat_match_response` `data:{room_id, state}`；无对手时 `success=false, code=408, message:"匹配超时"`。

**修复（`tools/pvp_sim/index.html`）**：
1. `autoPickCharacter()` 取角色改为**优先根级** `resp.characters || resp.data.characters || ...`。
2. `doAuth()` account 分支 `uid = resp.user_id || (resp.data && resp.data.user_id)`（根级优先），再 `autoPickCharacter()`。
3. `send()` 的 `@route:` key 与 `route` 字段**归一化**（`String(waitFor).replace(/_response$/,'')`）。
4. `handleMessage()` 兜底匹配**两侧都去 `_response` 再比**。
5. 三处调用 `waitFor` 显式改为 `_response` 全名（`pvp_flat_match_response`/`battle_room_action_response`/`battle_room_resume_response`），语义自解释。
