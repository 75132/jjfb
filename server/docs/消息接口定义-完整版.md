## 📋 统一响应格式

### 标准响应格式（使用 `send_response` 函数）

```typescript
interface StandardResponse {
    type: string;              // 格式：`{route}_response`
    success: boolean;          // 是否成功
    code: number;             // HTTP状态码（200=成功, 400=客户端错误, 401=未认证, 500=服务器错误）
    timestamp: number;        // 时间戳（Unix时间戳，秒）
    request_id?: string;      // 请求ID（用于客户端精确匹配响应）
    data?: any;              // 响应数据（可选）
    message?: string;        // 响应消息（可选）
}
```

**示例**：
```json
{
    "type": "get_player_response",
    "success": true,
    "code": 200,
    "timestamp": 1703123456.789,
    "request_id": "req_123456",
    "data": {
        "role_name": "测试角色",
        "level": 10
    },
    "message": "获取成功"
}
```

### 直接发送格式（保持向后兼容）

部分Handler直接使用 `websocket.send()`，格式可能略有不同：

```typescript
interface DirectResponse {
    type: string;            // 消息类型
    success: boolean;        // 是否成功
    message?: string;       // 响应消息（可选）
    // ... 其他字段直接放在根级别
    request_id?: string;    // 请求ID（如果请求中包含）
}
```

**示例**：
```json
{
    "type": "login_response",
    "success": true,
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "user_id": "user_123",
    "request_id": "req_123456"
}
```

### HTTP状态码定义

| 状态码 | 含义 | 使用场景 | 说明 |
|--------|------|----------|------|
| **200** | 成功 | 请求成功处理 | 标准成功响应 |
| **400** | 客户端错误 | 参数错误、业务逻辑错误 | 如：缺少必填参数、数据格式错误、业务规则违反 |
| **401** | 未认证 | Token无效、未登录 | 如：Token过期、Token无效、需要登录 |
| **404** | 资源不存在 | 资源未找到 | 如：角色不存在、物品不存在、好友不存在 |
| **500** | 服务器错误 | 服务器内部错误 | 如：数据库错误、未捕获的异常 |
| **503** | 服务不可用 | 服务暂时不可用 | 如：网络错误、服务超载 |

**错误响应示例**：
```json
{
    "type": "get_player_response",
    "success": false,
    "code": 404,
    "timestamp": 1703123456.789,
    "request_id": "req_123456",
    "message": "角色不存在"
}
```

## 🔐 认证相关消息

### 1. 登录请求 (`login`)

**功能**：用户登录，获取访问令牌

**请求**：
```typescript
interface LoginRequest {
    type: 'login';
    account: string;              // 账号（必填）
    password: string;             // 密码（必填）
    refresh_token?: string;       // 可选：用于刷新Token（如果提供，会验证并刷新）
    request_id?: string;          // 可选：请求ID（用于匹配响应）
}
```

**请求示例**：
```json
{
    "type": "login",
    "account": "test_user",
    "password": "password123",
    "request_id": "req_login_001"
}
```

**响应**（直接发送格式）：
```typescript
interface LoginResponse {
    type: 'login_response';
    success: boolean;
    message?: string;
    token?: string;                    // Access Token（JWT格式）
    refresh_token?: string;            // Refresh Token（用于刷新Access Token）
    token_expires_at?: number;         // Access Token过期时间（Unix时间戳，秒）
    refresh_token_expires_at?: number; // Refresh Token过期时间（Unix时间戳，秒）
    user_id?: string;                 // 用户ID
    request_id?: string;              // 请求ID（如果请求中包含）
}
```

**响应示例（成功）**：
```json
{
    "type": "login_response",
    "success": true,
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refresh_token": "refresh_token_abc123...",
    "token_expires_at": 1703209856,
    "refresh_token_expires_at": 1703296256,
    "user_id": "user_123456",
    "request_id": "req_login_001"
}
```

**响应示例（失败）**：
```json
{
    "type": "login_response",
    "success": false,
    "message": "账号或密码错误",
    "request_id": "req_login_001"
}
```

**注意事项**：
- 登录成功后，客户端应保存 `token` 和 `refresh_token`
- `token` 用于后续请求的认证（通过 `auth_request` 接口）
- `refresh_token` 用于刷新过期的 `token`（通过 `login` 接口传入 `refresh_token`）
- 如果 `refresh_token` 过期或被撤销，需要重新登录

```typescript
interface BagUseItemRequest {
```

```typescript
interface BagUseItemResponse {
    type: 'bag_use_item_response';
    success: boolean;
    code: number;
    timestamp: number;
    request_id?: string;
    data?: {
        item_id: number;
        target_type: string;
        remaining_quantity: number;    // 剩余数量（如果为0则已消耗完）
        pet_id?: string;               // 如果target_type是'Pet'
        effect_result?: {              // 物品效果结果（如果物品有效果配置）
            success: boolean;
            message?: string;
            // ... 其他效果相关字段（根据物品效果配置）
        };
    };
    message?: string;
```

```json

    "success": true,
    "code": 200,

    "data": {
        "item_id": 1001,
        "target_type": "Player",
        "remaining_quantity": 4,
        "effect_result": {
            "success": true,
            "message": "经验值增加100"
        }
    }
}
```

**响应示例（失败）**：
```json

    "type": "bag_use_item_response",
    "success": false,

    "request_id": "req_use_item_001",

}
```

**注意事项**：
- **精确定位**：强烈建议提供 `category` 和 `slot_index`，避免误操作
- **物品效果**：如果物品配置了效果系统，会返回 `effect_result` 字段
- **剩余数量**：使用后，如果 `remaining_quantity` 为 0，物品会被移除
- **目标类型**：
  - `Player`：对玩家生效（如：经验药水、金币包）
  - `Pet`：对机甲生效（如：机甲经验药水、属性提升道具）
- **机甲ID**：使用 `Pet` 类型时，必须提供 `pet_id`

## 📝 注意事项

### 1. 响应格式差异

- **标准格式**：使用 `send_response` 函数的响应，数据在 `data` 字段中
  ```json
  {
      "type": "xxx_response",
      "success": true,
      "code": 200,
      "timestamp": 1234567890,
      "data": { /* 实际数据 */ }
  }
  ```

- **直接格式**：直接发送的响应，数据字段直接在根级别（向后兼容）
  ```json
  {
      "type": "xxx_response",
      "success": true,
      /* 实际数据直接在这里 */
  }
  ```

### 2. request_id 字段

- **用途**：所有响应都应该包含 `request_id`（如果请求中包含）
- **重要性**：用于客户端精确匹配响应，避免误匹配问题
- **使用建议**：
  - 客户端发送请求时，生成唯一的 `request_id`（如：UUID、时间戳+随机数）
  - 服务器会自动将 `request_id` 添加到响应中
  - 客户端通过 `request_id` 匹配响应，而不是通过消息类型

**示例**：
```typescript
// 客户端发送请求
const requestId = `req_${Date.now()}_${Math.random()}`;
send({
    type: 'get_player',
    request_id: requestId
});

// 客户端接收响应
onMessage((response) => {
    if (response.request_id === requestId) {
        // 这是对应的响应
    }
});
```

### 3. 向后兼容性

   - 部分Handler仍使用直接发送格式，保持向后兼容
- 新功能建议使用标准响应格式（`send_response`）
- 客户端需要同时支持两种格式

### 4. 字段可选性

   - 大部分字段都是可选的（使用 `?` 标记）
   - 根据实际业务逻辑，某些字段可能必须存在
- **必填字段**：通常不标记 `?`，或在接口说明中明确标注

### 5. 测试模式

   - 大部分接口支持测试模式，可以通过 `user_id` 直接验证（跳过token验证）
   - 主要用于开发和测试环境
- **生产环境**：应禁用测试模式，强制使用Token认证

**测试模式示例**：
```json
{
    "type": "get_player",
    "user_id": "test_user_123"  // 测试模式，跳过token验证
}
```

### 6. 精确定位

   - 背包相关操作（使用物品、丢弃物品）支持通过 `category` 和 `slot_index` 精确定位
- **建议**：客户端在操作时提供这些字段，避免误操作
- **原因**：仅通过 `item_id` 可能无法唯一确定物品（同一物品可能有多个）

**精确定位示例**：
```json
{
    "type": "bag_use_item",
    "item_id": 1001,
    "category": 1,      // 物品分类
    "slot_index": 5    // 在当前分类中的索引
}
```

### 7. 分页加载

   - 机甲列表、背包物品等支持分页加载
- **优势**：减少数据传输量，提升性能
- **默认值**：
  - `page`: 从 0 开始
  - `page_size`: 默认 50（可根据实际情况调整）

**分页示例**：
```json
{
    "type": "get_robot_pets",
    "page": 0,
    "page_size": 20
}
```

### 8. Token 管理

- **Access Token**：用于API请求认证，有效期较短（如：1小时）
- **Refresh Token**：用于刷新Access Token，有效期较长（如：7天）
- **Token刷新**：通过 `login` 接口传入 `refresh_token` 刷新
- **Token撤销**：修改密码、完全登出会撤销所有Token

### 9. 错误处理

- **网络错误**：客户端应实现重试机制（指数退避）
- **业务错误**：根据 `code` 和 `message` 处理
- **Token过期**：自动使用 `refresh_token` 刷新，或提示重新登录

### 10. 并发控制

- 服务器端已实现请求序列化（同一用户的请求串行处理）
- 客户端应避免同时发送多个相同类型的请求
- 使用 `request_id` 确保响应匹配正确

#### 示例5：处理推送消息

```typescript
class MessageHandler {
    private responseHandlers = new Map<string, (response: any) => void>();
    
    constructor(websocket: WebSocket) {
        websocket.onmessage = (event) => {
            const message = JSON.parse(event.data);
            
            if (message.request_id) {
                // 这是响应消息
                this.handleResponse(message);
            } else {
                // 这是推送消息
                this.handlePushMessage(message);
            }
        };
    }
    
    // 等待响应
    waitForResponse(requestId: string): Promise<any> {
        return new Promise((resolve, reject) => {
            const timeout = setTimeout(() => {
                this.responseHandlers.delete(requestId);
                reject(new Error('请求超时'));
            }, 30000); // 30秒超时
            
            this.responseHandlers.set(requestId, (response) => {
                clearTimeout(timeout);
                this.responseHandlers.delete(requestId);
                resolve(response);
            });
        });
    }
    
    // 处理响应消息
    private handleResponse(response: any) {
        const handler = this.responseHandlers.get(response.request_id);
        if (handler) {
            handler(response);
        }
    }
    
    // 处理推送消息
    private handlePushMessage(message: any) {
        switch (message.type) {
            case 'bag_items_update':
                this.onBagItemsUpdate(message);
                break;
            case 'robot_pets_update':
                this.onRobotPetsUpdate(message);
                break;
            case 'chat_message':
                this.onChatMessage(message);
                break;
            case 'announcement':
                this.onAnnouncement(message);
                break;
            case 'robotcount_update':
                this.onRobotCountUpdate(message);
                break;
        }
    }
    
    private onBagItemsUpdate(message: any) {
        // 更新背包UI
        updateBagUI(message.items);
    }
    
    private onChatMessage(message: any) {
        // 显示聊天消息
        showChatMessage(message.text, message.sender);
    }
    
    // ... 其他推送消息处理方法
}
```

## 📚 常见问题解答（FAQ）

### Q1: 如何区分标准格式和直接格式的响应？

**A**: 查看响应的结构：
- **标准格式**：有 `code`、`timestamp` 字段，数据在 `data` 字段中
- **直接格式**：没有 `code`、`timestamp` 字段，数据直接在根级别

**示例**：
```typescript
// 标准格式
{
    type: 'xxx_response',
    success: true,
    code: 200,
    timestamp: 1234567890,
    data: { /* 数据 */ }
}

// 直接格式
{
    type: 'xxx_response',
    success: true,
    /* 数据直接在这里 */
}
```

### Q2: request_id 是必须的吗？

**A**: 不是必须的，但**强烈推荐使用**：
- 用于精确匹配请求和响应
- 避免并发请求时的响应匹配错误
- 建议客户端为每个请求生成唯一的 `request_id`

### Q3: Token 过期后如何处理？

**A**: 有两种方式：
1. **使用 refresh_token 刷新**：通过 `login` 接口传入 `refresh_token`
2. **重新登录**：如果 `refresh_token` 也过期，需要用户重新输入账号密码

**推荐流程**：
```typescript
// 1. 请求时检查Token是否过期
if (isTokenExpired()) {
    // 2. 尝试刷新Token
    const newToken = await refreshToken();
    if (newToken) {
        // 3. 使用新Token重试请求
        retryRequest();
    } else {
        // 4. 刷新失败，提示重新登录
        showLoginDialog();
    }
}
```

### Q4: 如何实现请求重试？

**A**: 建议使用指数退避策略：
```typescript
async function sendRequestWithRetry(request, maxRetries = 3) {
    for (let i = 0; i < maxRetries; i++) {
        try {
            return await sendRequest(request);
        } catch (error) {
            if (i === maxRetries - 1) throw error;
            // 指数退避：1s, 2s, 4s
            await sleep(Math.pow(2, i) * 1000);
        }
    }
}
```

### Q5: 背包物品如何精确定位？

**A**: 使用 `category` 和 `slot_index` 组合：

```typescript
// 获取背包时，记录每个物品的 category 和 slot_index
const bagItems = await getBag();
bagItems.forEach((item, index) => {
    item.category = item.category;
    item.slot_index = index; // 在当前分类中的索引

// 使用物品时，提供这些信息
await useItem({
    item_id: item.item_id,
    category: item.category,
    slot_index: item.slot_index

```

### Q6: 分页加载的最佳实践？

**A**: 
- **首次加载**：使用默认值（`page: 0`, `page_size: 50`）
- **加载更多**：递增 `page` 值
- **虚拟滚动**：结合虚拟滚动技术，按需加载
- **缓存策略**：缓存已加载的数据，避免重复请求

### Q7: 如何处理推送消息？

**A**: 推送消息是服务器主动发送的，不需要请求：
```typescript
// 监听所有消息
websocket.onmessage = (event) => {
    const message = JSON.parse(event.data);
    
    // 判断是推送消息还是响应消息
    if (message.request_id) {
        // 这是响应消息，通过 request_id 匹配
        handleResponse(message);
    } else {
        // 这是推送消息，根据 type 处理
        handlePushMessage(message);
    }
};

// 处理推送消息
function handlePushMessage(message) {
    switch (message.type) {
        case 'bag_items_update':
            updateBagUI(message.items);
            break;
        case 'chat_message':
            showChatMessage(message);
            break;
        // ...
    }
}
```
