> 状态：设计定稿 + 客户端已实装（`assets/Script/Game/BattleScene.ts`）+ 字段迁移完成
> 口径来源：用户明确规则（本次会话）
> **字段名：`AttackCount`（已全面取代原 `ParticleShield` 粒子护盾，默认值 1）**

---

## 一、机制定义（用户口径）

**不是「多打一次」，而是「把一次攻击的伤害拆成多段」。**

| 项 | 规则 |
|---|---|
| 总伤害 | **不变** —— 仍为 `damage = max(1, 攻击 − 防御)` |
| 段数 | **`N 段 = AttackCount`**（字段语义即「总段数」，默认 **1**） |
| 每段 | 各带**小幅区间波动**（含单段暴击式加伤），但幅度不离谱 |
| 总伤上限 | **N 段总和相对单次伤害最多 +20%**（不是 N 倍！） |

关键点：**攻击次数带来的是「伤害浮动上限 +20%」和「多段打击感」，不是 DPS 翻倍。**

## 二、为什么这样设计

1. **平衡安全**：若「攻击次数+N」等价于「伤害 ×(N+1)」，则顶配玩家 17272 普攻 ×3 = 5 万，直接击穿所有精英/Boss，数值体系崩塌。用户明确限定 +20% 上限，避免超模。
2. **手感收益**：多段弹数字 = 打击感强、暴击反馈密集，视觉爽感提升但数值可控。
3. **与「致命/暴击」属性解耦**：暴击走独立属性（Lethality），本机制的「小波动」只是每段分配差异，不重复计算暴击。

## 三、公式

```
输入：baseDamage（单次伤害）、attackCount（单位 AttackCount 字段，默认 1）
段数 segN = max(1, floor(attackCount))

if segN == 1:  return [baseDamage]

# 1) 总伤提升（0 ~ +20%，偏向低值避免每次顶满）
boost = rand()^1.6 * 0.20
targetTotal = floor(baseDamage * (1 + boost))

# 2) 每段权重（均分 × 0.65~1.35 随机波动）
weight[i] = (1/segN) * (0.65 + rand()*0.70)

# 3) 按权重分配，末段吸收舍入误差 → 保证 Σsegs == targetTotal
segs[i] = max(1, round(targetTotal * weight[i] / Σweight))   (i < segN-1)
segs[segN-1] = max(1, targetTotal - Σ前段)
```

**性质**：`Σsegs ∈ [baseDamage, baseDamage×1.20]`，恒成立。

### 取值优先级（`resolveAttackTimes`）
1. 顶层 `AttackCount` / `attackCount`（服务端已聚合，默认 1）→ 直接作为总段数；
2. 否则累加 `info.equipment` 各槽位 `attackCount`，总段数 `= 1 + Σ`；
3. 否则从 `effecttext` 解析「攻击次数+N」兜底；
4. 兜底返回 **1**。

## 四、伤害浮动区间一览

| 攻击次数 (AttackCount) | 段数 | 总伤区间 | 相对单次 |
|---|---|---|---|
| 1（默认） | 1 | [D, D] | 100% |
| 2 | 2 | [D, 1.20D] | 100%~120% |
| 3 | 3 | [D, 1.20D] | 100%~120% |
| N | N | [D, 1.20D] | **上限恒 120%** |

> 段数只影响「打击感/分配粒度」，不影响总伤上限 —— 避免高次数装备堆出超模。

> 补充：怪物侧凭 `AttackCount` 区分 —— 普通怪 = 1（单段），精英/Boss = 2（双段，配合其高 HP 强化压迫感）。这是 v4 公式引擎在 `monster_formula.py` 中按 `is_elite()` 分档自动给出的默认值，可被已有值覆盖。

### 段间节奏（视觉表现）
- **连续冒出**：每段伤害按 **0.18s** 间隔依次弹出数字（`scheduleOnce`），形成连击感。
- **弧形倒退飞行（2026-09-28 更新）**：每个数字从受击者身上冒出后，沿**抛物线（弧线）**向
  **受击者身后**（被击退方向）**倒退飞出**，一边飞一边淡出 —— 不是简单往上冒，而是「先上抛、再回落、横向倒退」的弧线轨迹。
  - 攻击方在左 → 受击者在右 → 数字**向右**抛出（先右上、再右下坠落）；
  - 攻击方在右 → 受击者在左 → 数字**向左**抛出（先左上、再左下坠落）；
  - **自己方受击同理**：数字从自己身上向自己身后（远离攻击方）飞出；
  - 新数字紧随其后冒出 → 连续弧线轨迹感。
- 末段后延迟 0.35s 再刷新血条，与原有节奏一致。

### 关键实现点（`RobotShow.showDamageNumber`）
- **每次调用生成独立容器** `DamagePop`（不再共用 `numberNode`、不再销毁上一个数字）——
  改为维护 `activeDamageNodes[]` 列表，各段数字互不干扰，才能"连续冒"。
- **抛物线公式**（容器本地坐标，`t` 为 0→1 的归一化进度，`dur≈0.9s`）：
  ```
  x(t) = vx · t            // vx = ±DAMAGE_ARC_SPEED（符号由 dirX 决定，向受击者身后）
  y(t) = vy · t − ½·g·t²   // vy = +DAMAGE_ARC_UP（先上抛）, g = DAMAGE_ARC_GRAVITY（向下）
  ```
  常量：`DAMAGE_ARC_SPEED=150`、`DAMAGE_ARC_UP=150`、`DAMAGE_ARC_GRAVITY=420`（像素/秒、像素/秒²）。
- **淡出**：前 20% 保持全亮（营造"冒出来"），其后线性淡出至 0。
- 签名：`showDamageNumber(value, isHeal, dirX?, dirY?, life=0.9)`，`dirX` 正=向右飞、负=向左飞，
  由调用方 `BattleScene.damageDriftFor(attackerSide)` 按击退方向传入（返回 `±1`）。
- 数字图集 `NumberIcon`：4 组各 0~9 共 40 帧 —— `Damage-*`（物理）、`bloodreturning-*`（治疗）、
  `defense-*`、`magic-*`，单帧 24×32。

1. **服务端同步**：若后续做服务端权威战斗结算，需把同一 `computeAttackSegments` 移植到服务端（当前服务端只传总伤害）。

4. **平衡复核**：+20% 上限意味着「攻击次数」对顶配实际收益有限（17272 → 最多 20726），属于「手感型」属性而非「强度型」，符合用户「不离谱」要求。
