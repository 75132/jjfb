# 地图叙事配置总规范（对齐 Cocos StoryManager + story_service）

## 1. 总原则

- 一个地图一个 JSON：`map_{mapId}.json` 或 `map_0_{code}_shared.json`
- 三层副本不是同图分层，而是三张独立地图（3 个 `mapId`）
- 所有交互统一挂在 `npcs[].events[]`，不再拆独立传送表
- `eventType` 用英文常量，额外保留 `eventTypeDesc` 中文备注便于策划阅读
- **服务端权威**：客户端 `StoryManager` 走 `story_interact` / `story_event_complete`，勿用 `skipServerRequirements` 上线

## 2. 事件类型命名（统一）

- `dialog`（对话）
- `choice`（选项，纯选项事件）
- `battle`（战斗，可先配 `choiceScriptId` 再开战）
- `teleport`（传送，通常配 `choiceScriptId` + `effects.teleport`）
- `task`（任务过渡 / Toast 提示）
- `shop` / `capture` / `pvp`（预留）

## 3. 顶层字段

| 字段                     | 说明                                                              |
| ------------------------ | ----------------------------------------------------------------- |
| `configVersion`          | 配置版本，热更新与缓存失效                                        |
| `mapCode`                | 与 `StoryManager.mapCode`、服务端 `story_maps` 一致               |
| **`tasks`**              | 任务定义（**勿再用 `quests`**，服务端 `_task_defs` 只读 `tasks`） |
| `client.dialogueScripts` | 对白脚本池                                                        |
| `client.choiceScripts`   | 选项脚本池                                                        |
| `npcs[]`                 | NPC 与事件链                                                      |
| `battles[]`              | 战斗策划数据（可选，运行时 battleRef 指向 `battle_refs.json`）    |

## 4. 事件结构（npcs[].events[]）

```json
{
  "eventId": "0_lead_01_e2",
  "eventType": "choice",
  "order": 2,
  "server": {
    "requirements": [{ "type": "event_done", "eventId": "0_lead_01_e1" }],
    "allowedChoiceIds": ["yes"],
    "effects": [{ "action": "task_accept", "taskId": 100001, "choiceId": "yes" }]
  },
  "client": {
    "choiceScriptId": "choice_join_team",
    "dialogueScriptId": "dlg_xxx",
    "taskUiHint": "任务过渡文案"
  }
}
```

### server.effects 支持

- `task_accept` / `task_complete`（可选 `choiceId` 过滤）
- `teleport`：`toMapId`, `toX`, `toY`（可选 `choiceId`）
- `give_item` / `add_exp` / `send_mail`

## 5. 选项脚本（client.choiceScripts）

```json
{
  "id": "no",
  "text": "我再想想",
  "npcReply": "NPC 反馈 Toast",
  "systemTip": "系统提示 Toast",
  "completesEvent": false,
  "forcedResult": "block"
}
```

| 字段               | 说明                                                     |
| ------------------ | -------------------------------------------------------- |
| `completesEvent`   | 默认 `true`；`false` 时不调用 `story_event_complete`     |
| `forcedResult`     | `start_battle` 强制开战；`block` 不推进；`teleport` 预留 |
| `allowedChoiceIds` | 写在 **server** 上，限制哪些选项可完成事件               |

**注意**：`completesEvent: false` 的选项不能出现在 `allowedChoiceIds` 中。

## 6. 战斗事件

- `server.battleRef` 必填（如 `battle_300001`）
- 流程：`story_interact` 写入 `pending_battle` → `battle_room_create(story_event_id)` → 胜后 `story_event_complete(battle_won=true)`
- 战前选项：`client.choiceScriptId` + 服务端返回 `action: choice_then_battle`

## 7. NPC 命名约定

- `npcUid`：如 `0_lead_01`（mapId_role_index）
- `prefabKey`：场景预制体 key

## 8. Juben 编辑器对齐

- 节点选项面板可编辑 `npcReply` / `systemTip` / `completesEvent` / `forcedResult`
- 工具栏 **「地图 JSON」**：校验 / 规范化 / 导出（`src/editor/map-runtime.ts`）
- 示例：`AItools/Sample/剧情脚本/map_0_test_base_shared.json`
- 同步到工程：
  - `server/data/story_maps/`
  - `assets/resources/Sample/剧情脚本/`

## 9. 对话写作口径

- 主线风格：防线、虫族、机甲、补给、前哨、守卫
- 战斗前用「准备进入战斗」，勿写「模拟胜利」
- 「否/暂缓」选项的 `systemTip` 须说明**不会推进**且如何重试
