# 压力测试工具使用说明

## 简介

`stress_test.py` 是一个用于测试游戏服务器性能的压力测试工具。它可以模拟多个并发用户连接服务器，执行各种游戏操作，并统计性能指标。

## 安装依赖

```bash
pip install websockets
```

## 使用方法

### 快速启动（推荐）

**Windows 用户:**
```bash
# 双击运行 run_stress_test.bat 或命令行执行
run_stress_test.bat
```

**Linux/Mac 用户:**
```bash
# 添加执行权限（首次运行）
chmod +x run_stress_test.sh

# 运行脚本
./run_stress_test.sh
```

### 命令行用法

```bash
# 测试 100 个并发用户，持续 60 秒
python stress_test.py --users 100 --duration 60

# 测试 500 个并发用户，持续 120 秒
python stress_test.py --users 500 --duration 120

# 高频模式测试（更频繁的操作，适合压力测试）
python stress_test.py --users 200 --duration 60 --high-frequency

# 超百位玩家高频操作测试（推荐用于服务器极限测试）
python stress_test.py --users 500 --duration 120 --high-frequency

# 指定服务器地址和端口
python stress_test.py --host 192.168.1.100 --port 8001 --users 200 --duration 60
```

### 参数说明

- `--host`: 服务器地址（默认: localhost）
- `--port`: 服务器端口（默认: 8001）
- `--users`: 并发用户数（默认: 100）
- `--duration`: 测试时长，单位秒（默认: 60）
- `--ramp-up`: 逐步增加用户的时间，单位秒（默认: 10）

### 测试场景

工具会模拟以下游戏操作：

1. **连接服务器** - WebSocket 连接
2. **用户登录** - 自动注册或登录（账号格式: `test_user_0001`）
3. **选择角色** - 自动选择第一个可用角色
4. **初始化数据** - 自动获取角色信息、背包、机甲列表
5. **游戏操作** - 根据模式执行不同操作：

**正常模式（默认）：**
- `bag_get` (30%) - 背包查询
- `get_robot_pets` (25%) - 机甲列表
- `get_character_info` (20%) - 角色信息
- `get_player` (10%) - 玩家信息
- `get_robot_pet_info` (8%) - 机甲详情
- `bag_use_item` (4%) - 使用物品
- `upgrade_robot` (2%) - 升级机甲
- `bag_write_random` (1%) - 随机写入

**高频模式（--high-frequency）：**
- `bag_get` (25%) - 背包查询
- `get_robot_pets` (20%) - 机甲列表
- `get_character_info` (15%) - 角色信息
- `bag_use_item` (12%) - 使用物品（写操作）
- `upgrade_robot` (10%) - 升级机甲（写操作）
- `bag_write_random` (8%) - 随机写入（写操作）
- `get_player` (5%) - 玩家信息
- `get_robot_pet_info` (3%) - 机甲详情
- `bag_discard_item` (2%) - 丢弃物品（写操作）

**真实行为模拟：**
- 写操作后自动刷新背包（模拟客户端行为）
- 操作序列：先获取数据，再执行操作
- 智能缓存：避免重复查询
- 操作间隔：正常模式 0.5-3秒，高频模式 0.1-0.5秒

## 测试结果

测试完成后会显示以下统计信息：

### 用户统计
- 总用户数
- 成功连接数及百分比
- 成功登录数及百分比
- 活跃用户数及百分比

### 请求统计
- 总请求数
- 成功/失败请求数及百分比
- 平均 QPS（每秒请求数）

### 按路由统计
- 每个路由的请求数
- 成功率
- 平均响应时间（毫秒）
- P95 响应时间（毫秒）
- P99 响应时间（毫秒）

### 总体响应时间
- 平均响应时间
- 中位数响应时间
- P95/P99 响应时间
- 最小/最大响应时间

## 性能指标参考

### 良好性能标准
- **连接成功率**: > 99%
- **登录成功率**: > 95%
- **请求成功率**: > 99%
- **平均响应时间**: < 100ms
- **P95 响应时间**: < 200ms
- **P99 响应时间**: < 500ms

### 500 并发用户目标
- 能够稳定维持 500 个连接
- 平均 QPS > 100
- 错误率 < 1%
- 响应时间符合上述标准

## 测试建议

### 逐步增加负载
1. **小规模测试** (50-100 用户)
   ```bash
   python stress_test.py --users 50 --duration 30
   ```

2. **中等规模测试** (200-300 用户)
   ```bash
   python stress_test.py --users 200 --duration 60
   ```

3. **大规模测试** (500+ 用户)
   ```bash
   python stress_test.py --users 500 --duration 120
   ```

### 监控服务器资源
在测试过程中，建议同时监控：
- CPU 使用率
- 内存使用率
- 网络带宽
- MongoDB 连接池使用率
- 服务器日志

### 分析瓶颈
如果测试结果不理想，检查：
1. **连接失败率高** → 检查服务器连接数限制
2. **响应时间长** → 检查数据库查询性能
3. **错误率高** → 检查服务器日志
4. **QPS 低** → 检查是否有性能瓶颈

## 注意事项

1. **测试账号清理**: 测试会创建大量测试账号（格式: `test_user_XXXX`），如需清理可以手动删除或编写清理脚本

2. **服务器资源**: 确保服务器有足够的资源（CPU、内存、网络带宽）来支持测试负载

3. **数据库性能**: 大量并发测试可能会对数据库造成压力，建议在测试环境中进行

4. **网络延迟**: 本地测试和远程测试的结果会有差异，建议在实际部署环境中也进行测试

## 故障排查

### 连接失败
- 检查服务器是否运行
- 检查防火墙设置
- 检查端口是否正确

### 登录失败
- 检查数据库连接
- 检查用户表结构
- 查看服务器日志

### 响应超时
- 检查服务器性能
- 检查数据库查询性能
- 增加超时时间（修改代码中的 timeout 参数）

## 扩展功能

- 添加更多游戏操作
- 调整操作频率
- 修改用户行为模式
- 添加更多统计指标
