## 零、v4 基准校正（本次会话用户纠正）

**纠正内容**：正确的参照系是「**满配玩家**」，不是「机甲 L60 裸值」。

| 参照 | 数值 | 来源 |
|---|---|---|
| 顶配普攻 | **17272** | 弗雷萨(双修4882) + 昆古尼尔(攻5760) + 月光微波炮(攻5590) + 霸者之翼(1040) |
| 顶配单体技能 | **~32000** | ×1.85 技能倍率 |
| 顶配群攻满伤 | **~23000** | ×1.33 技能倍率 |
| 20000 血精英 | 满配**应能秒杀** | 普攻 1.16 刀 / 技能 1 刀 |

→ 结论：**除精英/Boss 外，普通怪满配必须 1 刀；20000 血精英靠技能或满攻击次数普攻可秒** —— 这是设计基准，不是异常。
（v3 拿「机甲 L60 裸攻击 5430」当分母，得出了错误的「怪物攻击不足」判断。）

## 三、v3 修复方案（P0/P1/P2，保留供追溯）

### P0+P1：怪物强度回调 + 梯度收窄

| 参数 | v2（问题值） | v3（修正值） |
|---|---|---|
| `ATK_SCALE` | 2.2 | **0.75** |
| `DEF_SCALE` | 1.5 | **0.90** |
| `TIER_COEF` 区间 | 0.80~3.60（4.5x） | **0.85~1.60（1.9x）** |

**设计原则**：强度梯度靠**等级**拉开，而非系数叠乘。每只怪仍保留独立确定性系数（可复现、各不同）。

### P2：经验曲线平滑

保持 L1~L50 原设计，L51~L60 改为 **1.20x 平滑递推**：

```python
2580000,    # 50
3096000,    # 51   ← 原 4,696,700(1.82x断层)
3715200,    # 52   ← 原 8,550,000(1.82x断层)
4458200,    # 53
5349800,    # 54
6419800,    # 55
7703800,    # 56   ← 原 19,877,424(停滞)
9244600,    # 57
11093500,   # 58
13312200,   # 59
15974600,   # 60   ← 原 20,950,000
```

总累计 1.836 亿 → **1.009 亿**（降 45%），断层数 **0**。

## 四、健康模块（未改动）

### 装备体系
- 5 槽位：Weapon(25) / Gun(23) / Armor(138) / Dun(10) / Wing(17)
- 价格梯度 100~7800，需求等级 1~50
- 定位清晰：武器→格斗/射击、盾→护甲/抗性、翼→双属性+攻击次数
- **补零值设计合理**：机甲 g~j（命中/致命/侵蚀/抗性）公式为 0，靠装备补足

### 机甲公式
- 统一结构 `属性 = level × 系数 + 基数`
- 区分度靠 `ClassCoefficient.json`（如铁臂射击系数=0、鹰眼=0.95）
- L60 满级 HP 15480 / 攻击 5430 / 防御 796

## 五、后续建议（未执行）

1. **低等级怪池稀薄**：L8~L10 仅 4 只、L40 仅 3 只 → 建议补充低阶/中阶怪，或调整等级匹配区间
2. **MP 利用率**：怪物 MP 中位 4659 vs 机甲 9870（47%）→ 若技能消耗 MP，需确认够用
3. **服务端攻击次数**：客户端已实装分段；若后续做服务端权威结算，需移植同一算法（见 `docs/攻击次数机制设计.md`）
4. **暴击属性**：本机制的小波动 ≠ 暴击；暴击走 Lethality，需独立实装
5. **爆率/掉落**：`Items.json` 无掉落概率配置 → 经济闭环待补
