## 3. 三个必须知道的坑

### 坑 1：MV 的 z 层在这张图上依旧是「假分层」
- `z2` = 461 格草地(B238) + 728 格**空图块**(E779) + 11 格 C
- `z3` = 728 格草地(B238) + 227 格墙 + 166 格路 + 79 格植物
- **z2 的 728 格 E779 与 z3 的 728 格 B238 是同一批格子（交集 728/728）**；z2 其余 472 格也被 z3 的墙/路/植物盖住
- ⇒ **z2 完全不可见**。`E779` 源图块（MAP15 @ 144,48）**不透明像素 0/2304 = 完全透明**

**所以：分层依据是 tile id 段，不是 z 层。导出器要按 id 段分流。**

### 坑 2：B/C/D 三个槽挂的是同一张 `MAP1.png` → 240 组「同像素不同 id」
- `id = n`、`256+n`、`512+n`（n=0..239）**图像完全一样**
- 好处：这是「用 id 段编码语义」能成立的原因（同一张图可以在三个页签里各取一次）
- 代价：**在编辑器里 B/C/D 三个页签长得一模一样，只能靠人肉记忆选图块** → 容易画错段
- **已抓到实证**：`C 481` / `C 486` 各有 1 格画的是**纯草地**（视觉与 B238 完全相同），却被算进「墙壁」层
  - 影响极小（2 格 / 1200），但说明这个机制有系统性风险

### 坑 3：本图的 tileset 是新建的 `18「测试」`
- `flags` 数组长度只有 **1**（正常应为 8192）→ 通行性标记**不可用**
  - 意味着：**「植物不可通行」这个语义目前只存在于你的约定里，机器读不到**
  - 要做真正的碰撞/通行，必须补齐 flags，或另存一份通行表
- 槽位：`[A1..A5 全空, B=MAP1, C=MAP1, D=MAP1, E=MAP15]`

---

## 4. 建议（等拍板）

1. **把 B/C/D 换成三张不同的图**（或至少给 tileset 各槽换成有区分度的图集）
   - 现在三个页签同图 → 只能靠记忆，已出现 2 格误画
   - 换成 `MAP1` / `MAP2` / `MAP3` 后，编辑器里一眼就知道当前在画哪一层
2. **补齐 tileset 的 `flags`（8192 长）**，把「不可通行」真正写进数据
   - 否则拆层出来的「植物层」只是贴图，碰撞还得另建
3. **导出器口径**：`Map025.data` → 按 `tile id 段` 分流到 4 个图层
   - TMX 路线：4 个 `<layer>`（`Ground / Wall / Road / Plant`），TiledMap 组件零改动
   - PNG 路线：4 张整图叠加（已验证无损）
4. **顺手处理 z2**：z2 是废弃填充（含 728 格空图块）→ 导出时**直接忽略 z2，只取 z3** 即可
