### (3) id 段天花板 ≈ 8 层，永远无法"一直加"

```
B 0-255 │ C 256-511 │ D 512-767 │ E 768-1023     ← 4 页，页签原生支持，各 256 格
1024-1535        空白 512 个 id，无页签
A5 1536-1663     128 格（图宽 384，t≥1664 时 sx 越界），页签原生支持
1664-2047        空白 384 个 id，无页签
A1/A2/A3/A4 2048-8191   自动图块专用
```

→ 能画普通图块的页签**只有 5 个（A5+B+C+D+E）**；空白 id 共 **896 ≈ 3.5 页**，且**编辑器无入口**。

### (4) ✅ 正解：把「层」换个维度 —— 层 = 地图

- 一张地图承载一层，用 **地图树**（`MapInfos.json` 的 `parentId` + `order`）组织：
  `Map025 ★主图 ├ L1_地面 ├ L2_墙壁 ├ L3_路面 ├ L4_植物 ├ L5_屋顶 …`
- **无限层、0 魔改**，且每层**可用完整调色板**（不再被迫"一层只放 1 个图块"）
- 导出器口径：`总层序 = [地图树 order] × [id 段序 B→C→D→E]` → **一张图 4 层 × N 张图**
- **"页签"与"地图"的手感其实一样**（都是点一下），但地图方案**层名可见、不会画错层**

### (5) ⭐ 剧情口径（回答用户"其他的不好做剧情"）

> **MV 的事件（101 对话 / 102 选项 / 111 条件 / 201 传送 / 301 战斗 / 开关）只挂在 `MapXXX.json` 的 `events[]` 上，与页签/图块段毫无关系。**

- **口径：主图挂全部事件（== 用户原来写剧情的那张图），子图是纯画布、零事件**；导出时图层取自全部子图、事件取自主图，在 Cocos 侧重合成同一场景
- **等价口径**：**主图即 L1（地面层）**，层序取 `[地图树 order]`，主图天然排第一 → 事件与层同图。**两种都支持，让用户挑**
- **MV「测试游戏」看不到子图叠加**（玩家只进一张图）→ 两个补法：
  1. **`!` 零视差远景图**：`ImageManager.isZeroParallax = f => f.charAt(0) === '!'`（`rpg_managers.js:915`）；`Game_Map.parallaxOx` 里 `_parallaxZero → _parallaxX * tileWidth`（`rpg_objects.js:5625`）→ 名字以 `!` 开头的远景图**与地图 1:1 滚动**。把下层合成 PNG 丢 `img/parallax/` 即可当参考底图
  2. **导出器生成"合成主图"**：把 L1..Ln 压进主图 z0..z3（z0/z1 角色之下、z2/z3 盖住角色，由用户指定"第几层起遮挡"），事件数组原样带过去

### (6) 迁移口径（不推翻现有习惯）

**现有 Map025 的 B/C/D/E 用法原样保留**，只在 4 层装不下时**新建一张同尺寸兄弟地图**继续画 → 导出器天然支持 `4 × N`。

## 9.5 ⭐ 图块容量上限：每层到底能放多少图块（2026-10-01 03:5x 用户问）

### 硬上限（**官方图鉴文件实证**，不是推理）

| 页签 | id 段 | **图规格** | **格数** |
|---|---|---|---|
| **A5** | 1536–2047 | **384×768** | **128** |
| **B / C / D / E** | 0–1023 | **768×768** | 各 **256** |
| | | **合计** | **1152** |
| A1 / A2 / A3 / A4 | 2048–8191 | 768×576 / 768×576 / 768×384 / 768×720 | 自动图块 16 / 32 / 32 / 48 种，**放不了普通图块** |

- **`% 16` 写死**（`sy = (⌊t % 256 / 8⌋ % 16) * 48`）→ **图做得再高，第 17 行以后永远取不到**。
  Canvas `rpg_core.js:5012` 与 WebGL `rpg_core.js:5736` **两版逐字一致**。
- **最硬实证**：`img/tilesets/*.txt` 是官方图块图鉴（「英文名|日文名」逐行），**行数 = 格数**：
  `Outside_B.txt`=**256**、`Outside_C.txt`=**256**、`Outside_A5.txt`=**128**、`Dungeon_A1.txt`=**16**、`Dungeon_A2.txt`=**32**
  → 反证 **编辑器是按图片尺寸算网格的** ⇒ **图片尺寸 = 容量**
- 空白 id 段 `1024–1535`（512）+ `1664–2047`（384）**编辑器无入口**（`setNumber` 会算成 9/10 越界）
- **一个地图只能指定一个图块集** ⇒ **单图上限 = 1152**

### 扩容四步（从易到难）
1. **A5 槽别空着** → +128（0 成本，只是指一张 384×768 的图）
2. **图补到标称尺寸**（768×720 → 768×768）→ +16/槽，**同时消掉 3.00% 黑格**
3. **B/C/D 拆成三张不同的图** → +512（**最大一笔**，也顺带解决"三页签同名靠记忆"）
4. 到顶 1152 → **换图块集**（配合「层 = 地图」，每层可独立图块集 → **1152 × 层数**）

### 翻转图块很吃容量
原 / 水平 / 垂直 / 180° = **4 倍** → **64 个基础图块就吃掉一整层**。
建议：只做水平翻转（2 倍）；或交给 Cocos `Sprite.scaleX = -1`（代价：**编辑器里看不见翻转效果**）。

### 9.5.1 ⛔ A1–A4 自动图块槽：数量写死，**图片做大也扩不了**（2026-10-01 04:1x 用户追问「A2 只有 4×8」）

引擎把 `tileId 2048..8191` 整段当自动图块，**每 48 个 id = 1 个 kind**：

```js
getAutotileKind = floor((tileId - 2048) / 48)   // rpg_core.js:5293
tx = kind % 8 ; ty = floor(kind / 8)            // :5044
A2: bx = tx*2 ; by = (ty - 2) * 3               // :5080  → 单元 2 格 x 3 格 = 96x144 px
A3: bx = tx*2 ; by = (ty - 6) * 2               // :5085  → 2 x 2 = 96x96
A4: bx = tx*2 ; by = floor((ty-10)*2.5 + (ty%2 ? 0.5 : 0))   // :5090
sx = (bx*2 + qsx) * 24 ; sy = (by*2 + qsy) * 24 // :5106
```

| 槽 | kind 区间 | 数量 | 单元(px) | 标准图 | 网格 |
|---|---|---|---|---|---|
| A1 | 0–15 | 16 | 96×144 | 768×576 | 水面/瀑布（3 帧动画） |
| **A2** | **16–47** | **32** | 96×144 | 768×576 | **8 列 × 4 行** |
| A3 | 48–79 | 32 | 96×96 | 768×384 | 8 列 × 4 行 |
| **A4** | **80–127** | **48** | 96×96 | 768×720 | 8 列 × 6 行 |
| | | **128** | | | |

**三条结论：**
1. 用户看对了：**A2 = 8 列 × 4 行 = 32**，且是**硬上限**
2. **扩不了**：kind 区间由 `isTileA1..A4` 的 id 段写死；图做大的第 5 行属 `kind 48+` = **A3 的地盘**（引擎会拿 A3 的图 + A3 表来画）
3. **自动图块不能当独立图块** —— 每个 96×144 单元内部是"拼图零件"（上边/左右角/内角），铺到地图按邻居自动挑 shape。**编辑器里那个格子不是一张图，是一组拼图**
→ **能放「独立翻转图块」的仍然只有 A5 128 + B/C/D/E 各 256 = 1152**

（用户工程里 A2 图都是标准 768×576：World_A2 / Outside_A2 / Inside_A2 / Dungeon_A2）

```
事件：只从主图取（NPC / 传送 / 对话 / 开关），输出点位表 + 剧情 JSON
校验：N 层叠加 == MV 原生渲染，逐像素比对（md5 一致）
```

## 13. 图块集加工工坊 Tileset Studio（10-01 13:30 新建）

### 位置与启动
`jjfb/tools/tileset_studio/` → 双击 **`start.bat`** → `http://127.0.0.1:19850/`（端口占用自动 +1）

架构：Python 标准库 HTTP 服务（`server.py`，零第三方依赖）+ 浏览器前端（`web/`，无框架、无 CDN，离线可用）。

### 它解决什么
用户原话：「原地图只有一个方向的图块，没有水平翻转和垂直翻转后图块，所以我手动去 PS 了导致图块超出了 ABCD 那个的格子数量」
→ 正解：**用工具批量生成变体并排进空槽**，而不是硬塞进 A2 或手 PS。

### 功能面
| 环节 | 说明 |
|---|---|
| 切格 | 任意图集 PNG → 48×48 网格；点选 / 拖动框选 / Shift 加选 / 右键清标注 |
| 语义 | 地面 / 墙面 / 路面 / 可通行植物 / 不可通行物体 / 树冠(★上层) / 未标（数字键 1–6） |
| 变换 | 原图 · 水平镜像 H · 垂直翻转 V · 180° HV |
| 变体生成 | N 源 × 4 变换，自动填当前槽空位，装满安全停止不越界 |
| 槽位 | A5=128、B/C/D/E 各 256；五个页签独立编辑 |
| 自动分配 | 按语义落槽：地面→B / 墙面→C / 路面→D / 植物·物体→E |
| 导出 | 槽 PNG（补足标称尺寸）+ manifest + **8192 长 flags** |

### 语义 → flags（最值钱的一步）
```
0x0000  可通行        地面 / 路面 / 可通行植物
0x000F  四面不可通行   墙面 / 不可通行物体
0x0010  ★上层（盖住角色，不影响通行）  树冠
```
→ 把前几轮发现的「`flags` 读不到、不可通行只在约定里」这个洞补掉了。

### ⚠ 核心坑：canvas 预乘 alpha 改写全透明像素的 RGB
canvas 2D 内部 premultiplied alpha；`drawImage` → `toDataURL` 往返后 **`a=0` 的像素 RGB 被抹成 0**
（源图可能带 `(255,0,0,0)`）。
- **症状**：导出图与源图块「逐字节不等」，但 **alpha 通道完全一致、差异像素 100% 是全透明像素**（R/G/B 差可达 255）
- **影响**：肉眼零差异，但会污染回归断言（修之前 256 格有 88 格"不符"）
- **修法**（`web/app.js` `ensureCellCache`）：切格时就把 `a===0` 的 RGB 归零
  ```js
  const id = g.getImageData(0,0,TILE,TILE), d = id.data;
  for (let k=0;k<d.length;k+=4)
    if (d[k+3]===0 && (d[k]|d[k+1]|d[k+2])) { d[k]=d[k+1]=d[k+2]=0; touched=true; }
  if (touched) g.putImageData(id,0,0);
  ```
- **验证口径**（`_verify_out.py`）：`alpha 通道逐字节一致` **且** `全透明 RGB 归零后逐字节一致`。
  **别用** `piece.tobytes()==got.tobytes()` 直接比。修后 259 格全部 0 不符。

### 其他实现坑
- `ImageData.data.buffer` 可能带 byteOffset → `new Uint8ClampedArray(d.buffer,0,N)` 取错区域，**用 `d.slice(0,N)`**
- 768 宽导出图里取第 1 格必须**双层循环按 `(y*768+x)*4` 取**，`slice(0, 2304*4)` 取到的是第 0 行的像素（错）
- `body` 没设 `display:flex; flex-direction:column` → `flex:1` / `flex:none` 全部失效 → **footer 被挤出屏幕外**（截图底部空白）
- 大图集默认缩放要自适应：`fitZoom()` 取 `min(宽比,高比)` 再按 0.5 步进；zoom < 1 时不画网格
