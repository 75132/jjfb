# 高级压力测试使用指南

## 概述

本压力测试工具已根据实际客户端流程和游戏服务器最佳实践进行了优化，能够模拟超百位玩家同时进行高频操作。

## 核心特性

### 1. 真实玩家行为模拟

✅ **操作序列**：模拟真实客户端流程
- 先获取数据，再执行操作
- 写操作后自动刷新（如使用物品后刷新背包）
- 智能缓存，避免重复查询

✅ **操作频率**：
- **正常模式**：0.5-3秒间隔，适合日常测试
- **高频模式**：0.1-0.5秒间隔，适合极限压力测试

✅ **操作类型**：
- 读操作：背包查询、机甲列表、角色信息等
- 写操作：使用物品、升级机甲、丢弃物品等

### 2. 高频模式详解

高频模式（`--high-frequency`）专为服务器极限测试设计：

**特点：**
- 操作间隔更短（0.1-0.5秒）
- 包含更多写操作（30%+）
- 模拟玩家快速连续操作
- 适合测试服务器在高负载下的表现

**使用场景：**
- 服务器极限容量测试
- 数据库写入性能测试
- 并发控制机制验证
- 缓存系统压力测试

### 3. 超百位玩家并发

工具已优化支持超百位玩家同时在线：

**优化措施：**
- 异步并发处理
- 逐步增加用户（避免瞬间冲击）
- 智能错误处理
- 资源自动清理

**推荐测试规模：**
- 小规模：50-100用户（验证功能）
- 中等规模：200-300用户（性能测试）
- 大规模：500+用户（极限测试）

## 使用示例

### 基础测试

```bash
# 100用户，正常模式，60秒
python stress_test.py --users 100 --duration 60
```

### 高频压力测试

```bash
# 200用户，高频模式，60秒
python stress_test.py --users 200 --duration 60 --high-frequency
```

### 极限测试

```bash
# 500用户，高频模式，120秒（推荐用于服务器极限测试）
python stress_test.py --users 500 --duration 120 --high-frequency
```

### 自定义测试

```bash
# 自定义所有参数
python stress_test.py \
    --host 192.168.1.100 \
    --port 8001 \
    --users 300 \
    --duration 90 \
    --ramp-up 15 \
    --high-frequency
```

## 性能指标解读

### 关键指标

1. **连接成功率**：> 99% 为良好
2. **登录成功率**：> 95% 为良好
3. **请求成功率**：> 99% 为良好
4. **平均响应时间**：< 100ms 为良好
5. **P95响应时间**：< 200ms 为良好
6. **P99响应时间**：< 500ms 为良好

### 高频模式指标

在高频模式下，由于操作更频繁：
- 响应时间可能略高（正常）
- QPS会显著提升
- 需要关注数据库写入性能
- 需要关注缓存命中率

## 测试建议

### 渐进式测试

1. **第一步**：小规模测试（50用户，正常模式）
   ```bash
   python stress_test.py --users 50 --duration 30
   ```

2. **第二步**：中等规模测试（200用户，正常模式）
   ```bash
   python stress_test.py --users 200 --duration 60
   ```

3. **第三步**：高频测试（200用户，高频模式）
   ```bash
   python stress_test.py --users 200 --duration 60 --high-frequency
   ```

4. **第四步**：极限测试（500用户，高频模式）
   ```bash
   python stress_test.py --users 500 --duration 120 --high-frequency
   ```

### 监控要点

在测试过程中，建议同时监控：

1. **服务器资源**
   - CPU使用率
   - 内存使用率
   - 网络带宽

2. **数据库性能**
   - MongoDB连接池使用率
   - 查询响应时间
   - 写入操作延迟

3. **应用性能**
   - 请求处理时间
   - 错误率
   - 缓存命中率

## 常见问题

### Q: 高频模式和正常模式的区别？

A: 
- **正常模式**：模拟普通玩家行为，操作间隔0.5-3秒，主要是读操作
- **高频模式**：模拟活跃玩家或机器人，操作间隔0.1-0.5秒，包含更多写操作

### Q: 如何判断服务器是否达到极限？

A: 关注以下指标：
- 错误率 > 1%
- 响应时间显著增加（P95 > 500ms）
- 连接成功率 < 95%
- 服务器资源使用率 > 90%

### Q: 测试账号会占用数据库空间吗？

A: 是的，每个测试用户会创建：
- 1个用户账号
- 1个角色
- 可能创建机甲和背包数据

建议在测试环境中进行，或定期清理测试数据。

### Q: 如何清理测试数据？

A: 可以编写清理脚本，删除账号格式为 `test_user_*` 的所有数据。

## 最佳实践

1. **测试环境**：在独立的测试环境中进行，避免影响生产数据
2. **逐步增加**：从小规模开始，逐步增加负载
3. **监控资源**：实时监控服务器和数据库资源
4. **分析瓶颈**：根据测试结果找出性能瓶颈
5. **优化迭代**：根据测试结果优化服务器配置
