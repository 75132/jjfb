## 01:0x 事故修复：近身技「还是原地出招」——根因是技能目录根本没加载

   吞掉只留一条 warn → `SkillData.setSkillCatalog()` **从未被调用**（`_catalog = null`）。
2. `SkillData.skillRangeOf(null)` 兜底是 **`ranged`** → `isRangedSkill(null, false) === true`
   → 所有技能（含 `roubo=melee`）都被判成远程 → `meleeMove` 永不创建 → **原地出招**。
   `[近身技]` 诊断日志当时写在 `if (!skillRanged)` 里，所以连日志都没打 —— 完美静默。

### 修复（4 处 + 守卫）
1. `BattleScene.ts`：import 补 `JsonAsset`；`[近身技]` 诊断日志**改成无条件打印**
   （带 `key` / `range` / `目录未命中→按普攻口径` / `持枪=` / 判定结果），下次一眼可查。
2. `SkillData.ts isRangedSkill`：**读不到技能定义 → `return !!hasGun`**（持枪=远程，否则近身
   = **与普攻完全同口径**）；`none` 显式 return false；`dynamic` 未知规则也按普攻口径，
   不再兜底成 `ranged`。
3. `server/services/skill_service.py is_ranged_skill`：同口径镜像（`not isinstance(skill, dict)`
   → `has_gun_equipped(actor)`）。
4. `tools/_test_skilldata_client.cjs` +4 项、`tools/_test_skill_range.py` +4 服务端 +4 源码守卫
   （含「cc import 必须含 JsonAsset」这条防复发守卫）。

## 01:25 技能特效「被裁 + 报错」修复（RPG 移植 15 个 clip）

用户：「**报错了，还有你给我这个图怎么是不全的，被裁了？xukongdaji这个**」

### ① 报错 = 169 条 `Rect width exceeds maximum margin`
`[Scene] Rect width exceeds maximum margin: yinliyazhi-8/ 384 192`（01:24:31~32，169 条）
= `SpriteFrame.checkRect()`（引擎 93168 行）拿 `library/**@f9941.json` 里的**旧 rect(384)**
比新纹理(192)。根因：22.9 那次 UPSCALE 2→1 重生成把帧**原地缩小**、uuid 又还原过，
编辑器 library 缓存没跟上。引擎会 `reset()` 自愈，但红字刷屏。

### ② 「图被裁了」真根因 = 画布写死 192（不是缩放）
读 MV 源码 `js/rpg_sprites.js` 实证：MV 是 **16 个独立 cell Sprite**
（`createCellSprites` anchor 0.5，`sprite.x = cell[1]` 自由偏移），**根本没有 192 画布**；
`position=3` 的画面级动画锚在**屏幕中心**且图元 x 可到 ±408。

## 03:35 「能不能魔改 MV 让图层一直往下加」—— 调研结论（只读）

## 04:10 追问「A2 只有 4x8，只能截 32 个」—— 自动图块槽容量

### 用户问题
「但是我看a2只有4x8，才只能截取我32个方块」

### 钉死的引擎事实（js/rpg_core.js，逐行核对）
- `getAutotileKind = floor((tileId - 2048) / 48)`（:5293）—— **每 48 个 id = 1 个 kind**
- `tx = kind % 8 ; ty = floor(kind / 8)`（:5044）
- A2: `bx = tx*2 ; by = (ty - 2) * 3`（:5080）；A3 `(ty-6)*2`（:5085）；A4 `floor((ty-10)*2.5 + (ty%2?0.5:0))`（:5090）
- `sx = (bx*2 + qsx) * 24 ; sy = (by*2 + qsy) * 24`（:5106）→ **A2 列距 96px、行距 144px**

| 槽 | kind 区间 | 数量 | 单元(px) | 标准图 | 网格 |
|---|---|---|---|---|---|
| A1 | 0–15 | 16 | 96×144 | 768×576 | 水面/瀑布（3 帧动画） |
| **A2** | **16–47** | **32** | 96×144 | 768×576 | **8 列 × 4 行** |
| A3 | 48–79 | 32 | 96×96 | 768×384 | 8 列 × 4 行 |
| **A4** | **80–127** | **48** | 96×96 | 768×720 | 8 列 × 6 行 |
| | | **128** | | | |

（用户工程里 A2/A2 图都是标准 768×576：World_A2 / Outside_A2 / Inside_A2 / Dungeon_A2）

### 三条结论
1. **用户看得没错**：A2 = 8 列 × 4 行 = **32**，且这是**硬上限**
2. **扩不了**：kind 区间写死在 `isTileA1..A4` 的 id 段里；图做大后第 5 行属 `kind 48+` = **A3 的地盘**（引擎会拿 A3 的图 + A3 的表来画）
