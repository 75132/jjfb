## 二、装备类型定义（type 字段）

### 2.1 武器和枪械
- **type 1**: Weapon（重型武器）
- **type 2**: Weapon（轻型武器）
- **type 6**: Gun（重型枪械）
- **type 7**: Gun（轻型枪械）

**注意**：type 6 是重型枪械，type 7 是轻型枪械

### 2.2 通用装备
- **type 3**: Dun（盾牌）- 只能配轻型武器（type 2）和轻型枪械（type 7），不能配重型武器（type 1）和重型枪械（type 6）
- **type 4**: Wing（机翼）- 完全通用，不受任何限制
- **type 5**: Xinpian（芯片）- 完全通用，不受任何限制

### 2.3 职业固定装备（基于 Class）
- **Class 1（格斗）**: type 14（Toukai）、8（Jianjia）、11（Xiongkai）、17（Tuikai）、20（Shoukai）
- **Class 2（射击）**: type 15（Toukai）、9（Jianjia）、12（Xiongkai）、18（Tuikai）、21（Shoukai）
- **Class 3（全能）**: type 16（Toukai）、10（Jianjia）、13（Xiongkai）、19（Tuikai）、22（Shoukai）

## 三、装备限制规则

### 3.1 机甲类型限制（基于 RobotID）

1. **格斗型（MELEE_ROBOT_IDS）**：
   - ✅ 允许：武器（type 1、2）
   - ❌ 禁止：枪械（type 6、7）

2. **射击型（SHOOTING_ROBOT_IDS）**：
   - ✅ 允许：枪械（type 6、7）
   - ❌ 禁止：武器（type 1、2）

3. **全能型（ALL_ROUND_ROBOT_IDS）**：
   - ✅ 允许：轻型武器（type 2）、轻型枪械（type 7）
   - ❌ 禁止：重型武器（type 1）、重型枪械（type 6）

### 3.2 通用装备限制

1. **type 3（Dun/盾牌）**：
   - ✅ 允许：轻型武器（type 2）、轻型枪械（type 7）
   - ❌ 禁止：重型武器（type 1）、重型枪械（type 6）
   - 注意：装备盾牌时，如果已有重型武器（type 1）或重型枪械（type 6），则禁止装备

2. **type 4（Wing/机翼）**：
   - ✅ 允许：所有装备（完全通用，不受任何限制）

3. **type 5（Xinpian/芯片）**：
   - ✅ 允许：所有装备（完全通用，不受任何限制）

### 3.3 职业固定搭配（基于 Class）

1. **Class 1（格斗）**：
   - 只能装备：type 14、8、11、17、20

2. **Class 2（射击）**：
   - 只能装备：type 15、9、12、18、21

3. **Class 3（全能）**：
   - 只能装备：type 16、10、13、19、22

### 3.4 等级限制

- 遵守 JSON 中的 `requiredLevel` 字段
- 机甲等级必须 >= 装备要求的等级

## 四、验证逻辑流程

```
1. 检查等级限制（requiredLevel）
   ↓ 通过
2. 判断装备 type：
   - 如果是 3（Dun/盾牌）→ 检查是否已有重型武器（type 1）或重型枪械（type 6），如果有则禁止
   - 如果是 4（Wing/机翼）→ 无限制，允许装备
   - 如果是 5（Xinpian/芯片）→ 无限制，允许装备
   - 如果是 8-22（职业固定装备）→ 检查 Class 是否匹配
   - 如果是 1、2、6、7（武器/枪械）→ 检查机甲类型（RobotID）是否允许
   ↓
3. 如果装备的是武器/枪械（type 1、2、6、7），检查是否已有盾牌（type 3）：
   - 如果装备重型武器（type 1）或重型枪械（type 6），且已有盾牌（type 3），则禁止
   ↓ 通过
4. 允许装备
```

## 五、实现要点

1. **验证顺序**：先检查等级，再检查类型限制，最后检查冲突
2. **错误提示**：每个限制都要有清晰的错误信息
3. **性能优化**：使用缓存快速查找机甲类型和装备配置
4. **数据一致性**：在装备前验证，确保数据完整性
